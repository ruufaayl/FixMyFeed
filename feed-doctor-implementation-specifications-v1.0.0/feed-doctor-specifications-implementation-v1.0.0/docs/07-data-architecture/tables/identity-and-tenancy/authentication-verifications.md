# Table Specification — Authentication Verifications

## Purpose

Defines the physical PostgreSQL contract for Better Auth's short-lived email verification and password-reset records.

## Scope

This table is a global authentication primitive. It is not tenant-owned and MUST NOT contain organization, membership, role, session, or authentication-event state.

## Dependencies

- `/IMPLEMENTATION_BASELINE.md`
- `/AGENTS.md`
- `/docs/04-system-architecture/identity-architecture.md`
- `/docs/06-security-privacy-and-compliance/authentication-architecture.md`

## Functional Requirements

- The table MUST implement Better Auth's verification model through the approved Drizzle adapter.
- The lookup identifier MUST be a deterministic hash of the application-level identifier; plaintext email addresses and reset subjects are prohibited.
- The value MUST be an opaque, single-purpose verification secret and MUST NOT be written to logs or telemetry.
- Expired or consumed records MUST never authorize an operation and MAY be deleted asynchronously.
- Verification records MUST NOT substitute for immutable authentication events, which remain owned by T014.

## Non-functional Requirements

- The implementation MUST remain deterministic, open source, provider-portable, and free of recurring external dependencies.
- The table MUST support bounded identifier lookup and expiration cleanup.
- External email delivery MUST remain behind the documented authentication email port.

## Data and Security Requirements

- IDs MUST be application-generated UUIDv7 values.
- Identifiers MUST be hashed before reaching persistence or observability boundaries.
- Values MUST be generated by Better Auth and treated as credentials for their complete lifetime.
- Transport MUST use TLS and application errors MUST not disclose whether a user exists.

## Validation Rules

- Reject empty identifiers, values, and invalid expiration timestamps.
- Reject already-expired verification creation attempts.
- A verification value MUST be consumed only for its intended identifier and operation.
- Fail closed when persistence or email delivery does not complete.

## Performance Requirements

- Identifier lookups use `authentication_verifications_identifier_idx`.
- Cleanup scans use `authentication_verifications_expires_at_idx`.
- Expiration cleanup MUST be idempotent and bounded.

## Test Requirements

- Contract tests MUST verify the exact table name, columns, indexes, and UUIDv7 ID policy.
- Authentication factory tests MUST verify hashed identifiers and safe behavior when email delivery is unavailable.
- Migration tests MUST prove the migration is additive and reversible in documented reverse order.

## Acceptance Criteria

- The implementation, migration, physical registry, and this authority document agree on all six columns.
- No plaintext verification identifier or secret is logged or emitted to telemetry.
- No new paid service, secret, or environment variable is introduced.

## Physical Schema

| Column | Type | Null | Rules |
|---|---|---:|---|
| `id` | UUIDv7 | No | Primary key; application generated. |
| `identifier` | text | No | Deterministic hash of the application-level identifier. |
| `value` | text | No | Opaque Better Auth verification value. |
| `expires_at` | timestamptz | No | Server-side expiration boundary. |
| `created_at` | timestamptz | No | Database UTC timestamp. |
| `updated_at` | timestamptz | No | Changes on every mutation. |

## Constraints and Indexes

- Primary key: `authentication_verifications_pkey (id)`.
- Lookup index: `authentication_verifications_identifier_idx (identifier)`.
- Expiration index: `authentication_verifications_expires_at_idx (expires_at)`.
- The table has no organization or user foreign key because the identifier is deliberately pseudonymous and ephemeral.

## Retention and Deletion

Consumed and expired records SHOULD be removed promptly by an idempotent cleanup job. Legal hold does not extend credential validity.

## Migration Rules

The table is introduced additively. Rollback first disables authentication traffic that can create verification records, then drops `authentication_verifications` after dependent authentication application code is rolled back.
