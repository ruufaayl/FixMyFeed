# Table Specification — Encrypted Credentials

## Purpose

Defines the physical PostgreSQL contract for organization-owned provider
credentials protected by the T015 application-managed authenticated-encryption
envelope. The repository owner approved this new authority on 2026-08-06.

## Ownership and access

Every query and mutation requires an explicit `organization_id`. Credential rows
are referenced by UUID only; jobs, events, logs, analytics, client responses, and
connector configuration MUST NOT contain plaintext, encryption keys, ciphertext,
nonces, or authentication tags. Only the server-side vault may decrypt a row, and
plaintext is supplied to a bounded callback for immediate provider use.

## Physical Schema

| Column | Type | Null | Rules |
|---|---|---:|---|
| `id` | uuid | No | UUIDv7 primary key generated by the application before encryption. |
| `organization_id` | uuid | No | Restrictive foreign key to `organizations`; first in tenant indexes. |
| `provider` | text | No | Lowercase approved connector identifier; 1–64 characters. |
| `credential_type` | text | No | Lowercase credential-kind identifier; 1–64 characters. |
| `status` | text | No | Closed lifecycle: `active` or `revoked`; defaults to `active`. |
| `algorithm` | text | No | Fixed to `aes-256-gcm`. |
| `key_id` | text | No | Lowercase SHA-256 key identifier; never raw key material. |
| `nonce` | bytea | No | Exactly 12 random bytes; unique per encryption operation. |
| `ciphertext` | bytea | No | Authenticated encrypted payload; 1–65,536 bytes; never returned. |
| `auth_tag` | bytea | No | Exactly 16 bytes. |
| `idempotency_key` | text | No | Bounded request identity; unique per organization and actor. |
| `created_by_user_id` | uuid | No | Restrictive foreign key to the creating user. |
| `expires_at` | timestamptz | Yes | Provider expiry; expired credentials fail closed. |
| `revoked_at` | timestamptz | Yes | Present exactly when status is `revoked`. |
| `created_at` | timestamptz | No | Database UTC creation timestamp. |
| `updated_at` | timestamptz | No | Changes on rotation or revocation. |
| `version` | integer | No | Positive optimistic-concurrency token; starts at 1. |

## Constraints and indexes

- Unique creation identity: `(organization_id, created_by_user_id, idempotency_key)`.
- Primary list index: `(organization_id, created_at DESC, id DESC)`.
- Provider lifecycle index: `(organization_id, provider, status)`.
- Tenant and actor foreign keys use restrictive deletion.
- The database enforces identifier, status, algorithm, envelope-size, revocation,
  idempotency-length, and positive-version checks.

## Encryption and rotation

AES-256-GCM uses a fresh 12-byte nonce and 16-byte tag. Versioned authenticated
additional data binds the envelope to its credential ID, organization, provider,
and credential type. `DATA_ENCRYPTION_KEY` is encryption-active;
`PREVIOUS_DATA_ENCRYPTION_KEY` is decryption-only. Rotation decrypts an old envelope
and rewrites it under the active key with an optimistic version predicate.

## Lifecycle and failure handling

Creation is idempotent and rejects payload drift. Access to missing, cross-tenant,
expired, revoked, tampered, or unkeyed credentials fails with stable redacted
errors before provider execution. Revocation is idempotent and terminal. Observer
failure cannot change a durable result.

## Retention and deletion

Revoked ciphertext remains inaccessible while required for incident response or
audit correlation. Purge requires the applicable retention/legal-hold policy and
a separately reviewed contract migration or deletion workflow; ciphertext is
never copied into audit records.

## Migration and rollback

Migration `0004_t015_encrypted_credential_vault` is an additive create-table
migration after T016's `0003`. Never edit an applied migration, snapshot, or
journal entry. Rollback is application-first: stop writes, revoke or migrate active
credentials, verify backup/restore evidence, obtain operator approval, and only
then use a reviewed corrective-forward contract migration.
